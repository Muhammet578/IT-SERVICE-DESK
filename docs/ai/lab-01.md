# Журнал работы с ИИ — лабораторная работа №1

## 1. Цель

Создать минимальное серверное веб-приложение без фреймворка на PHP 8.4+, используя Composer, PSR-4, ООП, HTTP и Front Controller.

## 2. Запрос ИИ-аналитику

> Ты — архитектор PHP-приложений. Предложи минимальную архитектуру учебного приложения без фреймворка на PHP 8.4+, с Composer, PSR-4 и Front Controller. Контроллеры не должны содержать бизнес-логику. Сначала опиши архитектуру и последовательность реализации.

### Результат анализа

Проект разделён на слои:
- `Http` — получение запроса, формирование ответа и маршрутизация;
- `Controller` — обработка конкретных HTTP-маршрутов;
- `Domain` — предметные сущности;
- `Service` — прикладная логика и предоставление данных.

Единая точка входа `public/index.php` подключает Composer autoload, создаёт объект запроса, регистрирует маршруты, вызывает маршрутизатор и отправляет ответ.

## 3. Принятые решения

1. Использовать `declare(strict_types=1)` во всех PHP-файлах.
2. Использовать namespace `App\\` с PSR-4-маппингом в `src/`.
3. Сделать `Request` и `Response` неизменяемыми объектами (`readonly`).
4. Использовать `DateTimeImmutable` для временных отметок.
5. Возвращать JSON для `/health`.
6. Возвращать HTML для пользовательских страниц.
7. Экранировать выводимые значения через `htmlspecialchars`.
8. Возвращать HTTP 404 для неизвестного маршрута.
9. Не показывать пользователю внутренние детали исключений; техническую информацию записывать в error log.

## 4. Адаптация задания

По просьбе автора учебного проекта калькулятор `/quote` не реализуется. Вместо него добавлен маршрут `/tickets`, демонстрирующий предметную область будущего курсового проекта IT Service Desk. Это изменение необходимо явно согласовать с преподавателем, если исходный перечень маршрутов является обязательным и неизменяемым.

## 5. Запрос ИИ-тестировщику

> Проанализируй доменную сущность Ticket и сервис TicketCatalog. Подготовь unit-тесты для корректного создания заявки и проверки граничных/ошибочных значений: неположительный идентификатор, пустое название, неизвестный статус и неизвестный приоритет. Проверь, что каталог возвращает демонстрационные заявки.

### Ожидаемые проверки

- корректная заявка создаётся;
- идентификатор должен быть положительным;
- название не должно быть пустым;
- статус должен входить в допустимый список;
- приоритет должен входить в допустимый список;
- каталог возвращает три демонстрационные заявки.

## 6. Команды проверки

```bash
composer install
composer dump-autoload
composer test
php -S localhost:8000 -t public
```

HTTP-проверки:

```bash
curl -i http://localhost:8000/
curl -i http://localhost:8000/health
curl -i http://localhost:8000/about
curl -i http://localhost:8000/tickets
curl -i http://localhost:8000/unknown
```
