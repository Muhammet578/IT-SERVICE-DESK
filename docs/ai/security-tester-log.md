## 1. Использование ИИ при разработке

Ниже — краткое резюме реально обсуждавшихся этапов разработки, **не дословные цитаты и не утверждения об успешном автоматическом тестировании**.

| Обсуждавшийся вопрос | Предложенный подход | Контроль разработчика |
|---|---|---|
| Как реализовать роли в проекте с сущностью `Role` | Преобразовать доменные роли admin/manager/technician/user в `ROLE_*`, задать `role_hierarchy` | Проверить `debug:config security` и фактический доступ |
| Как организовать авторизацию | Использовать Symfony Security, парольный hasher, CSRF для login/logout | Проверить вход/выход, ошибки формы, хранение хеша |
| Как запретить операции с чужими заявками | `TicketVoter` (`VIEW`, `EDIT`, `CHANGE_STATUS`, `DELETE`) и серверные проверки | Функциональные тесты 200/403 и чужих ID |
| Как запретить вход отключённым аккаунтам | `UserChecker` и флаг `isActive` | При разработке проверялись отключение и восстановление пользователя; повторить тест |
| Как сохранять фильтры | Symfony Session только для периода и статуса | Убедиться, что Session не содержит паролей |
| Как защитить удаление | POST, CSRF-токен, разрешение Voter | Поддельный токен должен запрещать удаление |
| Как обновить интерфейс | Classic и Vice City в Twig/CSS/JS | Не подменять визуальными ограничениями серверные проверки |
