Лабораторная работа №4 — IT-SERVICE-DESK
1. Тема и цель
Тема: разработка веб-интерфейса с Twig, Symfony Forms и Validator.

Цель: продолжить проект IT-SERVICE-DESK, реализовать формы создания и редактирования пользователей, валидацию данных, безопасный поиск и сортировку, а также проверить работу интерфейса функциональными тестами.

Исходное учебное задание адаптировано к предметной области IT-SERVICE-DESK: вместо абстрактных клиентов и заказов используются пользователи и заявки технической поддержки.
2. Технологии
- PHP 8.4 и Symfony 7.4;
- Twig и Bootstrap 5 (локальные статические файлы);
- Symfony Form, Validator и CSRF;
- Doctrine DBAL для SQL-запросов без перехода на ORM;
- MariaDB / MySQL;
- PHPUnit и Symfony WebTestCase.
Работа выполнена в каталоге symfony-app репозитория IT-SERVICE-DESK. Разработка продолжается в ветке lab-04.
3. Реализованная функциональность
3.1. Страницы и шаблоны
Используется общий шаблон templates/base.html.twig, наследование шаблонов (extends), блоки (block), подключаемые части (include), циклы (for) и условия (if).

Оформлены главная страница, страница «О проекте», панель управления, списки пользователей и заявок, просмотр заявки, формы создания и редактирования пользователя. Подключены навигационная панель и отображение flash-сообщений. Отдельная страница просмотра пользователя удалена как избыточная для текущего объёма работы.

Для демонстрации Twig-фильтров предусмотрены следующие применения (перед сдачей следует проверить их наличие в текущих файлах):
Фильтр	Пример
upper	{{ project_name|upper }}
length	{{ tickets|length }}
trim	{{ ticket.title|trim }}
default	{{ ticket.title|default('Без названия') }}
lower	{{ user.email|lower }}


3.2. Работа с пользователями
- UserCatalog получает пользователей из MariaDB через Doctrine DBAL.
- UserFormData и UserType используются при создании пользователя.
- UserEditData и UserEditType используются при редактировании имени и email.
- Контроллер обрабатывает GET и POST, выполняет редирект после успешного сохранения и показывает flash-сообщения.
- При создании пароль сохраняется как хеш через password_hash().
- Редактирование не изменяет пароль и роль пользователя.
- Дублирующийся email обрабатывается через UniqueConstraintViolationException, сообщение выводится рядом с полем.
- Поиск по имени/email выполняется параметризованным SQL-запросом; сортировка ограничена разрешёнными колонками id, name, email.
Основные маршруты: /users, /users/new, /users/{id}/edit, /tickets и /tickets/{id}.
3.3. Валидация и безопасность
В моделях данных используются ограничения Symfony Validator: NotBlank, Length и Email. Свойства формы допускают null, чтобы пустые данные могли пройти через механизм валидации без ошибки типов.

Формы содержат CSRF-токен. Twig экранирует выводимые пользовательские значения. Для SQL используются параметризованные запросы, а поле сортировки проверяется по белому списку.

Ограничение текущей версии: авторизация и разграничение прав для управления пользователями ещё не реализованы; операции создания и редактирования следует использовать только в локальном учебном окружении до внедрения контроля доступа.
4. Тестирование
Ранее существовавшие тесты маршрутов были обновлены после удаления страницы /users/{id}. Для форм добавлен tests/Controller/UserFormTest.php.

Функциональные проверки включают:
- доступность основных страниц и ответы HTTP 200/404;
- JSON-ответ /health и параметры /request-info;
- присутствие полей формы создания пользователя;
- наличие CSRF-токена и отклонение поддельного токена;
- отклонение некорректных полей (пустое имя, неверный email, короткий пароль);
- экранирование HTML в поисковом запросе;
- безопасную обработку недопустимого поля сортировки.
Для тестового окружения подготовлена отдельная база it_service_desk_test. Параметры подключения хранятся в локальном .env.test.local, который не должен попадать в Git. В тестовом окружении Doctrine добавляет суффикс _test к имени БД, указанному в DATABASE_URL.

Проверки lint:twig и lint:container завершились успешно. После исправления модели данных пользователь подтвердил успешный запуск набора из 12 тестов. Точное количество assertions следует взять из итогового вывода PHPUnit, если оно требуется в отчёте.

Команды проверки из каталога symfony-app:
php bin/console lint:twig templates
php bin/console lint:container
php bin/phpunit --no-progress
5. Использование ИИ (AI Log)
ИИ использовался как помощник в разработке и обучении:
1. Для объяснения разделения ответственности между контроллером, сервисом, моделью формы и Twig-шаблоном.
2. Для обсуждения структуры UserType/`UserEditType` и правил Symfony Validator.
3. Для диагностики ошибки повторяющегося email и отображения FormError.
4. Для выяснения причин пропусков значений AUTO_INCREMENT в MariaDB.
5. Для диагностики конфигурации PHPUnit и тестовой базы данных.
6. Для подготовки примеров негативных тестов CSRF, валидации, XSS и безопасной сортировки.
7. Для улучшения интерфейса Twig/Bootstrap и подготовки данной документации.
Решения проверялись локально в браузере и средствами Symfony CLI/PHPUnit. Изменения в коде и Git выполнялись разработчиком.
