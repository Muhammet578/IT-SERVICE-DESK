Начиная с лабораторной работы №3, в этом же репозитории развивается отдельная версия на Symfony 7.4 (symfony-app/). Старая реализация на чистом PHP сохранена.
Важно: по условию ЛР №1 калькулятор /quote исключён. Вместо него добавлен учебный маршрут /tickets, соответствующий теме курсового проекта IT Service Desk. Это адаптация задания, а не реализация исходного калькулятора. Если преподаватель требует строго все маршруты из задания, /quote и QuoteCalculator придётся добавить отдельно.

Лабораторная работа №5 — Doctrine ORM, аналитика и пагинация
Пятая лабораторная посвящена переходу от прямых запросов DBAL к Doctrine ORM 3 для новых сценариев. В Symfony-приложении реализованы сущности и связи, миграция, Fixtures, агрегирующие выборки и Dashboard. Старые страницы и формы сохранены, когда их переработка не требовалась.
Адаптация задания: учебные сущности клиентов, товаров и заказов заменены предметной моделью IT Service Desk (пользователи, заявки, категории, статусы, комментарии). Это не буквальная реализация исходного задания про продажи; при строгой проверке предметной области необходимо согласовать адаптацию с преподавателем.

Doctrine Entity и связи
В symfony-app/src/Entity/ добавлены семь сущностей:
Entity	Назначение	Связи
Role	Роль пользователя	User → Role
User	Учётная запись	Ticket → User (автор и исполнитель)
Ticket	Заявка технической поддержки	Автор, исполнитель, категория, приоритет, статус
Category	Категория	Ticket → Category
Priority	Приоритет	Ticket → Priority
Status	Статус заявки, включая признак конечного состояния	Ticket → Status
Comment	Комментарий к заявке	Comment → Ticket, Comment → User


Используются атрибуты Doctrine, связи ManyToOne и внешние ключи. Для неназначенного исполнителя допускается NULL.
База данных, миграции и Fixtures
Для новой ORM-модели используется локальная база it_service_desk_orm. Существующая база it_service_desk прежних лабораторных не заменяется. Переменная подключения задаётся через .env.local.

Миграция находится в symfony-app/migrations/, фикстуры — в symfony-app/src/DataFixtures/AppFixtures.php. Демонстрационный набор включает 3 роли, 20 пользователей, 30 категорий, 4 приоритета, 4 статуса, 50 заявок и 100 комментариев. Загрузка Fixtures предназначена только для тестовой локальной БД: стандартная загрузка может очищать таблицы.
Репозитории, выборки и статистика
- TicketRepository — заявки по статусу, автору, периоду и постраничная выборка.
- UserRepository — активные пользователи, рейтинг по количеству заявок, поиск/сортировка/пагинация.
- CategoryRepository — топ категорий по количеству заявок.
- DashboardService — сбор статистики из ORM-репозиториев и DQL.
Для запросов используются QueryBuilder, DQL, агрегат COUNT, GROUP BY, сортировка, Doctrine Paginator и параметризованные условия. В списке пользователей сортировка ограничена полями id, name, email.

На странице /dashboard отображаются:
- число пользователей и заявок;
- число завершённых и незавершённых заявок по признаку Status::isFinal;
- среднее число заявок на пользователя;
- топ-5 пользователей и топ-5 категорий по числу заявок.

Лабораторная работа №6 — безопасность, роли и управление заявками
Шестая лабораторная развивает Symfony-версию IT-SERVICE-DESK: добавлены аутентификация, авторизация, управление доступом и сценарии работы с заявками. Основная предметная модель остаётся неизменной: User, Role, Ticket, Status, Category, Priority, Comment.
Symfony Security
- App\Entity\User реализует интерфейсы пользователя и пароля, хранит хеш пароля, роль и признак активности.
- Вход по email через app_login, выход — app_logout с CSRF-защитой.
- security.yaml включает password hasher, entity provider, main firewall, иерархию ролей и правила access_control.
- UserChecker запрещает вход неактивным пользователям.
- Публичная самостоятельная регистрация не используется как основной способ создания учётных записей: менеджер или администратор создаёт сотрудников через /users/new. Если старый /register ещё присутствует в рабочем дереве, его удаление/перенаправление необходимо проверить отдельно.
Заявки и разграничение доступа
- Пользователь работает со своими обращениями; специалист — со своими и назначенными ему, менеджер/администратор получают расширенный доступ по правилам приложения.
- TicketVoter контролирует операции VIEW, EDIT, CHANGE_STATUS, DELETE.
- Название и описание редактируются через Symfony Form; изменение статуса производится отдельным защищённым действием.
- Удаление отправляется POST-формой с CSRF-токеном и подтверждением на клиенте.
- Список заявок фильтруется по статусу с пагинацией; выбранный фильтр хранится в Session.
Аналитика и интерфейс
- Dashboard поддерживает периоды 7 дней / 30 дней / всё время. Количество пользователей и рейтинги показываются за всё время; показатели заявок зависят от выбранного периода.
- Twig-шаблоны оформлены на Bootstrap 5. Поддерживаются две цветовые схемы Classic и Vice City, адаптивные страницы, форма входа, профиль, пользователи и заявки.
- В Vice City на главной странице предусмотрен векторный фон заката с пальмами.
Ограничения и статус завершения
- В тестовом окружении успешно выполнены Doctrine-миграция, Fixtures и doctrine:schema:validate.
- Старые функциональные PHPUnit-тесты из предыдущих лабораторных требуют адаптации под Symfony Security; последний полный прогон не был успешным (12 тестов, 8 failures, 2 errors).
- Подготовленные тесты безопасности и модель угроз могут храниться в docs/security/ и symfony-app/tests/Functional/, если они добавлены в репозиторий; само их наличие не означает успешного запуска.
- Финальный тег lab-06-final создаётся после окончательной фиксации изменений; в README не утверждается, что он уже опубликован.
